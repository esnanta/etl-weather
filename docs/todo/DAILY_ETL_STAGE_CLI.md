## Purpose

Verify the existing standalone CLI entry points against **one already available, complete request partition** without generating fresh CDS requests or overwriting immutable files.

Default complete CLI: `python -m scripts.run_pipeline`. Optional stage CLIs: `python -m scripts.run_extract`, `python -m scripts.run_transform`, `python -m scripts.run_load`.

The configured dates, variables, provider, dataset, and bbox must match the exact existing artifact identity. Multi-month periods produce independent monthly partitions; **restrict the verification to one known complete partition**.

## Critical safeguards

- Do **not** run a stage if its required checkpoint does not exist and validate.
- A missing RAW checkpoint means `run_extract` and `run_pipeline` may submit CDS requests.
- A missing transformed checkpoint means `run_transform` and `run_pipeline` may create Parquet.
- `run_load` and `run_pipeline` can write PostgreSQL unless the unchanged-partition fast-skip conditions all match; prefer a disposable or explicitly authorized test database.
- RAW and Parquet must remain immutable; a resumed transformed checkpoint must reject changed RAW checksum.
- Idempotency is scoped to deterministic `request_key`, not a global deduplication rule.
- Do not reset or destroy data as part of this validation.
